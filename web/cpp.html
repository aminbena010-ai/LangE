De C++ a Rivo

C++ y Rivo se compilan ambos a nativo, pero con objetivos distintos: C++ maximiza el control y la abstracción de bajo nivel; Rivo maximiza la legibilidad con un lenguaje pequeño, tipado y sin gestión manual de memoria.

Ver la documentación completa

Sin humo: Rivo no tiene clases, plantillas, lambdas, namespaces ni la STL. No pretende sustituir a C++ para motores, RAII o programación de sistemas. Su nicho es la lógica clara y compilada; lo que ya tienes en C++ se puede seguir llamando desde Rivo con external (solo tipos simples).

Lado a lado

El mismo programa en ambos lenguajes

C++

#include <iostream>
#include <vector>
#include <string>

int doble(int n) {
    return n * 2;
}

int main() {
    std::vector<std::string> nombres = {"Ana", "Luis"};

    for (const auto& nombre : nombres) {
        std::cout << nombre << ": " << doble(21)
                  << std::endl;
    }
    return 0;
}

Rivo

fn doble(n:int) -> int:
    return n * 2

fn main():
    var nombres:list<string> = ["Ana", "Luis"]

    for nombre in nombres:
        print(f"{nombre}: {doble(21)}")

El range-for pasa a for x in lista:, std::cout desaparece y la plantilla implícita de vector<string> se convierte en un tipo explícito list<string>.

C++ (mapa y búsqueda)

std::map<std::string, int> edades;
edades["Ana"] = 20;

auto it = edades.find("Ana");
if (it != edades.end()) {
    std::cout << it->second << std::endl;
}

Rivo (mapa directo)

var edades:map<string, int> = ["Ana": 20]

# una clave inexistente aborta; revísala con try/catch
try:
    print(edades["Ana"])
catch error:
    print("sin dato: " + error)

Diferencias importantes

Lo que C++ hace y Rivo no

POO

Sin clases ni herencia

No hay constructores, sobrecarga, polimorfismo ni visibilidad public/private de clases. La privacidad en Rivo es la función que empieza por _.

Genéricos

Sin plantillas

No hay template ni concept. Las colecciones genéricas del lenguaje son list<T> y map<K, V>, y ya vienen resueltas.

Funciones

Sin lambdas ni sobrecarga

Una función tiene un nombre y una firma. Dos funciones con el mismo nombre son un error, no una sobrecarga.

Memoria

Sin RAII, punteros ni new

No hay new/delete, smart pointers ni movimiento. Strings, listas y maps los gestiona el runtime.

Tipos

Ocho tipos, nada más

Sin size_t, int64_t, unsigned, enum ni struct. Agrupar datos hoy se hace con maps y listas.

Cabeceras

Sin #include ni STL

Sin <vector>, <string> ni <map>: las colecciones son del lenguaje y la stdlib se importa con import texto, etc.

Qué gana tu código: desaparecen los errores de compilación kilométricos de plantillas, los segmentations fault por punteros colgantes y la gestión manual de memoria. Lo que queda es la lógica, con errores apuntando a archivo, línea y columna.

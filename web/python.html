Rivo para programadores de Python

Rivo bebe directamente de Python: indentación significativa, sintaxis legible y f-strings. Si vienes de Python, te sentirás en casa en minutos — pero hay diferencias reales que conviene conocer antes de escribir la primera línea.

Ver la documentación completa

La diferencia que lo cambia todo: Python es dinámico; Rivo es estáticamente tipado y obliga a escribir el tipo en cada declaración. No hay inferencia, no hay conversión implícita y no hay variables globales.

Lado a lado

El mismo programa en ambos lenguajes

Python

def doble(numero: int) -> int:
    return numero * 2


def main():
    nombres = ["Ana", "Luis"]
    edades = {"Ana": 20, "Luis": 25}

    for nombre in nombres:
        print(f"{nombre}: {edades[nombre]}")

    if len(nombres) > 1:
        print("varios")
    elif len(nombres) == 1:
        print("uno")
    else:
        print("ninguno")


main()

Rivo

fn doble(numero:int) -> int:
    return numero * 2

fn main():
    var nombres:list<string> = ["Ana", "Luis"]
    var edades:map<string, int> = [
        "Ana": 20,
        "Luis": 25
    ]

    for nombre in nombres:
        print(f"{nombre}: {edades[nombre]}")

    if len(nombres) > 1:
        print("varios")
    else:
        if len(nombres) == 1:
            print("uno")
        else:
            print("ninguno")

Observa: def pasa a fn, los tipos son obligatorios y el diccionario es un map<K, V> escrito con corchetes. elif es igual que en Python.

Diferencias importantes

Lo que Python hace y Rivo no

Rivo es deliberadamente pequeño. Estas ausencias son diseño, no deudas pendientes.

Tipos

Sin conversión implícita

var d:float = 7 / 2 es un error de tipo: 7 / 2 es int (división entera hacia cero). Escribe 7.0 / 2. En Python esto pasaría sin más.

Sintaxis

elif como en Python

Las ramas múltiples se encadenan con if, elif y else. No existe elseif.

Expresiones

Sin comprensiones ni lambdas

No existen list comprehensions, generadores ni lambda. Usa for, while y funciones con nombre.

Ámbito

Sin variables globales

var y const se declaran dentro de funciones (y módulos). A nivel global, el compilador lo rechaza.

Comparaciones

Cadenas sin orden

== y != comparan el contenido de las cadenas como en Python, pero < y > no están permitidos sobre cadenas, ni la igualdad sobre listas y maps.

Errores

Fallos que abortan

Un índice fuera de rango o una clave inexistente terminan el programa con IndexError/KeyError, como en Python antiguo. La única red de seguridad es try/catch.

Sin POO. El diseño actual de Rivo no incluye clases, herencia, métodos ni métodos dunder. Si tu proyecto gira alrededor de objetos, Rivo no es (todavía) tu lenguaje.

Convención de nombres: los builtins del runtime están en inglés (print, split, to_int…), mientras que la biblioteca estándar está en español (matematicas, texto, fecha…). Ninguno de los dos espacios puede duplicar nombres.
